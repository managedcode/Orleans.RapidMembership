# Testing and qualification

The owner requires automatic discovery and entirely in-memory membership. The process/consensus inventory below now uses discovered peers and RAM membership; prior fixed-seed results do not qualify the corrected runtime. The new MulticastDiscoveryTests use actual UDP discovery and TCP nonce exchanges without configured peer IPs, including isolation and disappearance.

[CONTRIBUTING](../CONTRIBUTING.md) owns executable local commands. [Membership requirements](Features/RapidMembership.md) maps native contracts to cases. CI and Release are independent: CI verifies behavior and coverage; Release builds and pushes packages without waiting for CI or feed indexing.

## Main acceptance: actual Orleans processes and clients

The principal acceptance tests use native Aspire `AddProject` resources running actual Orleans silos and external native Orleans clients. They invoke generated grain contracts over Orleans transport. They do not synthesize membership rows, replace grain execution or use an in-memory test cluster as evidence of process recovery.

| Case | Actual behavior checked |
| --- | --- |
| `AspireMembershipTests` | Three silos form a cluster; a real external client discovers gateways and calls a grain before/after abrupt loss, coordinator restart, non-voter join and graceful departure. |
| `ThirtyRealSilosRecoverFromZeroAndConcurrentChurnWithContinuousClients` | Zero → ten → twenty → five; return to twenty; concurrent ten joins and ten crashes; total loss; existing clients recover with ten; grow to thirty; graceful reduction to fifteen and return to thirty. |
| `LostVoterMajorityRejectsFreshIncarnationsUntilCompleteClusterRestart` | Real coordinator crashes remove a table quorum; network reads/writes cannot acknowledge; a fresh incarnation cannot restore lost promises. Complete process loss then permits a fresh group and existing-client recovery. |
| `ThirtyRealSilosStartTogetherFromZeroAndServeExternalClients` | Thirty real silos start directly from zero, agree on exact active membership and execute actual external grain calls on every live silo. |
| `RealSiloShutdownJoinsZeroExitAndRestartRecoversExternalClients` | Aspire invokes native application shutdown on a real non-voter, requires process exit code zero, then restarts it while the same external clients continue grain calls. |
| `AllCoordinatorsGracefullyLeaveTogetherAndTheirReplacementsKeepServingTheSameClients` | Three actual coordinators leave a six-silo cluster together; replacements must hold the table and the same external clients must continue before and after the departed processes return. |
| `NativeHostTests` | Public provider registration starts an actual silo and a separate Orleans client host; gateway discovery and grain calls use real transports. This in-process host test also measures public startup code coverage. |

After each live topology change, all four external clients invoke native Orleans `IManagementGrain.GetHosts(true, cancellationToken)` and require the exact expected active silo addresses and generations, with every returned status Active. Counts and original host sets are recorded per client. While all silos are stopped, management RPC must be unavailable; an empty fabricated host list cannot satisfy that phase.

Four continuing clients verify request nonces, native silo addresses, activation IDs and increasing sequences for each unchanged activation. Convergence requires exact native silo address/generation sets on every live process. Each live process must execute a grain call. A count-only match cannot pass. The zero phase drains in-flight work, checks no subsequent successes and keeps the same clients for recovery.

Scale cases allow 45 minutes for the complete churn schedule, 15 minutes for a cold thirty-silo start and 10 minutes for voter-majority recovery. Each convergence/client-progress phase allows 10 minutes. The native scale runner allows 75 minutes; its CI job allows 90 minutes including build and artifact collection. Initial automatic formation has a separate five-minute deadline. The actual test-node and external-client membership operation deadline is two minutes and the peer deadline is five seconds. HTTP state observations allow three minutes, within the ten-minute phase deadline. These deadlines preserve every membership and real grain-call assertion. Independent xUnit cases use at most four concurrent test threads; each case retains its original internal writer, silo and client concurrency. A native host is always stopped in a finally block even when its StartAsync fails.

AppHost owns startup, native resource commands and shutdown. Crash commands kill the actual child executable and await its exit. Graceful stop uses an Aspire HTTP resource command that calls the test node’s native StopApplication after the response completes, waits for process exit and requires exit code zero. The test-node host allows three minutes for joined shutdown. Resource readiness precedes observations. Convergence observations run with bounded concurrency of five; every configured live process is still read and checked against the complete expected native identity set. Each session keeps RAM membership and bounded rotating native silo logs. Cleanup joins clients, log watchers and AppHost resources after success, failure or cancellation.

## Supporting evidence

Real HTTP/2 consensus tests cover concurrent CAS, twenty/thirty independent writers, majority-accepted recovery before commit notification, identity/secret rejection, unavailable quorum, bounded history and cancellation. SameHostTransportTests protects local-interface routing through loopback, recipient-incarnation rejection, and unchanged remote, DNS, IPv6 and TLS authorities. Provider membership listeners bind all IPv4 interfaces and permit loopback. Native protocol transport enables this routing only for those provider listeners; its general default is unchanged. Advertised addresses and membership certificates retain their original identity. RAM replica tests protect promises, detached snapshot content, incarnation fencing and old/new quorum state handoff. A native gRPC interceptor observes cancellation of an actual unfinished join; the same endpoint must answer a subsequent real request.

Windows, Linux and macOS each run the complete zero-to-thirty scenario in a separate GitHub job with real local silo processes and external clients. The macOS jobs use GitHub’s standard `macos-15-intel` runner with 14 GB RAM ([runner specifications](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)). Native RAPID unit, real-network and Aspire suites are supporting mandatory gates.

Provider time is supplied by `System.TimeProvider` through DI. Runtime registration defaults to `TimeProvider.System`. `TimeProviderTests` injects `FakeTimeProvider` and advances expiration and cancellation deadlines explicitly while using real UDP and HTTP/2 transports. Expiry is checked at the exact thirty-second boundary and immediately after it; old authenticated packets must not refill an expired slot, and a fresh peer must be admitted. Held native RPCs and complete operations must cancel when their clock reaches the deadline, then the same transport must perform a successful write/read. This does not claim deterministic scheduling or exhaustive race exploration.

The owner selected native TimeProvider qualification instead of Clockwork. All original upstream Clockwork sources and 423 cases remain unchanged in the separate `RapidCluster.UpstreamSimulation.slnx`; [CONTRIBUTING](../CONTRIBUTING.md) gives its supplemental command. Its large batched case has a recorded race-tracker memory failure. It is not part of the main solution, provider CI or NuGet. No failed simulation is reported as passing. [ADR-0002](ADR/0002-native-time-provider-qualification.md) records this boundary.

## Coverage

`eng/verify-coverage.py` reads the original native Cobertura report for `ManagedCode.Orleans.RapidMembership`. The whole assembly requires at least 80% line and 70% branch coverage, including its generated code. Every critical source listed in `eng/verify-coverage.py` requires 90% line coverage. The gate merges line observations for compiler-generated state machines by original source line and retains the input report SHA-256 in `coverage-gate.json`; it removes no executable product code.

The native collector configuration enables static managed instrumentation with automatic restoration so small native API members are instrumented before JIT inlining. It adds no source exclusions and changes no threshold. Original reports remain the gate input.

The provider percentage is not the coverage of the upstream protocol, transport, test nodes or an entire distributed process tree. CI retains separate original unit/network reports. Child silo execution is proved by process observations and real grain responses; a parent-process coverage report alone does not establish it.

## Artifacts and limits

CI retains `qualification-ubuntu-latest`, `qualification-windows-latest`, `qualification-macos-15-intel` and `qualification-scale-ubuntu-latest`, `qualification-scale-windows-latest`, `qualification-scale-macos-15-intel` artifacts with original TRX, coverage and native phase/log evidence. A failed, cancelled, incomplete or skipped case does not qualify a gate. Local focused reports and platform CI are reported separately.

Process-kill restart proves the tested process contract. It does not establish arbitrary power-loss durability, filesystem behavior on an untested deployment, performance improvement or production readiness. Use original report/run identities when stating a result.

The real-silo profile uses a twenty-second native Orleans probe timeout with ten-/forty-second adaptive bounds, a ten-minute join-attempt deadline, five-second table refresh and thirty-second heartbeat publication. The former five-second probe profile declared live processes dead after probe timeouts on hosted runners, and a cold thirty-silo join exceeded the previous five-minute native join budget. These are bounded native timing settings; failure detection remains enabled. Exact process identity, membership, abrupt loss, recovery and client-progress assertions remain mandatory. Their final platform repeat is required.

Grain-triggered fatal-process tests select an observed activation on either a coordination voter or an ordinary silo. The real client invokes Environment.FailFast through that test-only grain, the owning Aspire resource must exit with a nonzero code, and the same grain identity must reactivate with a new activation and silo identity. All four continuing clients then verify the exact three-silo active set with native IManagementGrain, followed by four silos after restart with a new generation. These cases never expose a crash operation in the provider package. The scale workload is capped at thirty silo processes; the provider imposes no thirty-silo product limit.

Native Orleans probes and membership gossip remain enabled and own native liveness/status propagation. Provider discovery and quorum operations must also work before Orleans admission and after quorum loss, so they cannot depend on grain/broadcast routing through an already formed Orleans cluster. Orleans broadcast channels provide best-effort application notifications, not bootstrap discovery or membership-table CAS.

FakeTimeProvider discovery cases advance virtual time while waiting for repeated real UDP announcements, including startup packet loss; they also isolate their UDP port. Upstream Aspire health assertions explicitly use the separate HTTP health endpoint declared by that AppHost. Protocol traffic remains HTTPS/HTTP2 with its existing development-certificate checks; health endpoint selection does not disable certificate validation.

Quorum reads preserve the highest committed prefix when another replica retains accepted work from the same or an older slot. ReadRepairTests forces the real HTTP/2 read and repair quorums to include that lagging replica, verifies every replica catches up without an empty consensus slot, then requires a healthy heartbeat and read. Accepted work above the committed prefix still follows the existing quorum recovery path. The original prepare/accept preemption assertions remain unchanged.
