# Automatic in-memory Orleans membership

## Owner correction

The provider must discover peer addresses itself and keep membership entirely in memory. Require no SeedEndpoints, ListenEndpoint IP or StorageDirectory. The prior fixed-voter/durable-directory design is superseded and must not be released. Remove its runtime configuration and exclusive storage implementation when replacing it; retain original RapidCluster protocol suites and MIT attribution.

Automatic local-network discovery uses real UDP multicast with authenticated, cluster-scoped beacons. Peers take addresses from actual network responses; external clients observe discovered listeners without becoming table participants. A complete process loss loses membership state and requires fresh cluster formation. Application grain storage remains an independent Orleans responsibility.

The owner selected RAPID's consistent-configuration behavior. Table handoff needs frozen old and installed new majorities; isolated minorities cannot silently become the same cluster. Discovery expiry never authorizes quorum reduction. Canonical configuration identities, incarnation fencing, permanent old-view barriers, recovery of accepted/committed snapshots and the RAM replica are implemented as components. Repeated installation preserves newer promises; delayed handoffs cannot be retargeted to skip a configuration. They are not yet wired into automatic host bootstrap or the silo/client transport.
